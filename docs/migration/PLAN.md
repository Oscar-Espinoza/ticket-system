# Next.js → SvelteKit migration plan

> **Status: done (2026-11-05).** Cut over in e185ca9; the Next.js app is gone. This file is kept for its conventions (file layout, props contract, generated action wrappers), which still apply to new code. Parity, API, performance and review results: PARITY_REPORTS.md, perf-next-vs-kit.json, WAVE2_REPORTS.md.

Goal: the same app — every page, feature, permission check and look — on
SvelteKit 3.1 + Svelte 5.57 instead of Next.js 16 + React 19. The server code in
`src/lib` (~22k lines: issue service, auth, sync, integrations, jobs) and the
server actions in `src/app/actions` are reused **unchanged**; what is rewritten is
the React UI (`src/components`, ~53k lines), the pages/layouts (`src/app/**`) and
the API route handlers.

API facts for SvelteKit 3 / Svelte 5 / bits-ui / dnd-kit / tiptap / Better Auth:
**`docs/migration/SVELTEKIT_REFERENCE.md`** (researched against the published
packages; its final "Verification" section wins over the sections above it).
Read the parts you need before writing code. Do not rely on memory of
SvelteKit 2 (`$lib`, `$app/stores`, `svelte.config.js`, `invalidateAll` and
`ORIGIN` are all gone or deprecated in 3.x).

## How the migration runs

Both apps live in one repo on `main` until cutover. Next keeps building from
`next.config.ts` and `src/app`; SvelteKit builds from `vite.config.ts` and
`src/routes`. They share `src/lib`, `src/db`, `public/` and `node_modules`.

| Thing | Next (old, stays until cutover) | SvelteKit (new) |
|---|---|---|
| Pages, layouts | `src/app/**/page.tsx`, `layout.tsx` | `src/routes/**/+page.svelte`, `+page.server.ts`, `+layout.svelte`, `+layout.server.ts` |
| API routes | `src/app/api/**/route.ts` | `src/routes/api/**/+server.ts` |
| Components | `src/components/**.tsx` | `src/lib/components/**.svelte` (same sub-path) |
| Client state/hooks | `use-*.ts`, React contexts | `src/lib/components/**/<name>.svelte.ts` (runes) |
| Client libs with React | `src/lib/{auth-client,undo,palette-commands,hotkeys}.ts`, `src/lib/sync/outbox.ts` hook | `src/lib/svelte/<name>.svelte.ts` |
| Server actions | `src/app/actions/*.ts` (`'use server'`) | **unchanged**, called through generated wrappers `@/lib/actions/<file>` |
| Config | `next.config.ts`, `tsconfig.json` | `vite.config.ts`, `tsconfig.svelte.json` |
| Styles | `src/app/globals.css` | `src/app.css` (copy + shadcn-svelte variants + @fontsource Geist) |

Already in place (foundation, done by the coordinator):
- `vite.config.ts`: adapter-node (adapter-vercel when `VERCEL` is set), remote
  functions + async Svelte on, `'@' → src` alias, `public/` as static assets,
  `.env*` loaded into `process.env`, `NEXT_PUBLIC_*` inlined, and aliases that
  map `next/headers|cache|navigation|server`, `react` (for `cache`) and
  `better-auth/next-js` to `src/lib/kit/*` shims — so shared server code runs
  as-is under SvelteKit.
- `src/hooks.server.ts`: self-host boot in `init`, CSRF check (with the SAML/
  OAuth/Slack exemptions), Better Auth session in `event.locals.user/session`,
  `/api/auth/*` answered by Better Auth.
- `src/app.d.ts`, `src/app.html` (density boot script, PWA meta), `src/app.css`.
- `src/lib/remote/*.remote.ts` + `src/lib/actions/*.ts`: generated by
  `npm run kit:gen-actions` from every `'use server'` file (208 actions).
- `src/routes/api/health`, `src/routes/manifest.webmanifest`.

## Conventions for builders (follow exactly — other lanes depend on them)

### Files and names
1. A React component file `src/components/<dir>/<file>.tsx` becomes
   `src/lib/components/<dir>/<file>.svelte` **when it exports one component**.
2. When the `.tsx` exports several components, the one whose kebab-case name
   equals the file name (or the default export) is `<file>.svelte`; every other
   exported component `PascalName` is `src/lib/components/<dir>/<kebab-name>.svelte`
   (e.g. `issue-row.tsx` exporting `IssueRow` and `IssueRowSkeleton` →
   `issue-row.svelte`, `issue-row-skeleton.svelte`). Non-exported helper
   components may stay inside the file as snippets or become local files.
3. `src/components/ui/*.tsx` (shadcn primitives) become **folders**:
   `src/lib/components/ui/<name>/` with one `.svelte` per part and an
   `index.ts` exporting every part under the **same names as the React
   exports** (`import { DropdownMenu, DropdownMenuTrigger, DropdownMenuContent }
   from '@/lib/components/ui/dropdown-menu'`). Same for
   `src/components/ui-icons/` → `src/lib/components/ui-icons/index.ts`.
   Other barrels (`index.ts` in a component dir) become
   `src/lib/components/<dir>/index.ts` re-exporting the `.svelte` files under
   the React names.
4. Hooks, contexts and stores (`use-*.ts`, `*-context.tsx`, `*-store.ts`,
   `selection.tsx`, …) become `src/lib/components/<dir>/<file>.svelte.ts`
   (runes). Keep exported function names, minus React-isms: `useFoo()` stays
   `useFoo()` when it reads context or creates state; providers become
   `setFooContext(value)` + `useFoo()`/`getFooContext()` built on Svelte's
   `createContext` (see reference §Svelte 5 Context).
5. These **React-free** modules are imported **as they are, from their current
   path** (do not copy them): `src/components/app-shell/routes.ts`,
   `customers/customer-model.ts`, `cycles/cycle-utils.ts`,
   `dashboards/widget-data.ts`, `dashboards/widget-model.ts`,
   `documents/document-model.ts`, `editor/embeds.ts`, `editor/text-edits.ts`,
   `editor/upload.ts`, `epics/epic-model.ts`, `inbox/when-options.ts`,
   `initiatives/initiative-model.ts`, `issue-hierarchy/attachment-utils.ts`,
   `issue-hierarchy/tree.ts`, `oauth/oauth-model.ts`,
   `people/activity-summary.ts`, `productivity/issue-defaults.ts`,
   `productivity/new-issue-bus.ts`, `recurring/schedule.ts`,
   `security/user-agent.ts`, `workspaces/role-rules.ts`, `workspaces/slug.ts`,
   `workspaces/workspace-types.ts`, and everything in `src/lib` except the five
   client files listed in the table above. If such a module turns out to need a
   change for Svelte, put the Svelte version next to the component instead and
   say so in your report; never edit a file another lane owns.
6. Imports use the `@/` alias and no extension for `.ts` (`@/lib/utils`),
   explicit `.svelte` for components (`@/lib/components/issues/issue-row.svelte`).
7. New Svelte-only TypeScript outside `src/routes` and `src/lib/{components,svelte,kit,remote,actions}`
   must be named `*.svelte.ts` (the Next `tsconfig.json` excludes those).

### Props: same contract as the React component
- Same prop names and types. `className` → `class`. `children: ReactNode` →
  `children?: Snippet`. A render prop `renderX: (a) => ReactNode` → `x: Snippet<[A]>`
  (drop the `render` prefix). `ReactNode` props that are plain content →
  `Snippet`. Callback props keep their names (`onSelect`, `onOpenChange`, …).
- Refs: `ref`/`forwardRef` → `ref = $bindable()` on the element.
- Controlled+uncontrolled pairs (`open`/`onOpenChange`, `value`/`onValueChange`)
  → keep both props and also support `bind:open` / `bind:value` with
  `$bindable()`.
- Typed props with `let { … }: Props = $props()`; spread the rest onto the root
  element where the React component spread `...props`.

### React → Svelte 5 (see reference "React 19 to Svelte 5 mapping")
- `useState` → `$state`; derived values → `$derived`; `useMemo` → `$derived.by`;
  `useEffect` → `$effect` (only for real side effects; derive instead of
  syncing); `useLayoutEffect` → `$effect.pre`; `useRef` (DOM) → `bind:this`;
  `useRef` (value) → plain `let`; `useId` → `$props.id()`;
  `useSyncExternalStore` → `createSubscriber` or a `.svelte.ts` class with
  `$state`; `memo`/`useCallback` → nothing.
- `useTransition` around a server call → a `pending = $state(false)` flag set
  around the awaited call (or the call's own pending state).
- `useOptimistic` → set local `$state` immediately, call the action, roll back
  on error (keep the exact rollback/toast behaviour of the React code).
- `useActionState(action, init)` → `let state = $state(init)`, a `pending`
  flag, and a submit handler `state = await action(state, new FormData(form))`
  using the generated `(prev, formData)` wrapper. Keep `name` attributes.
- `next/dynamic` → `{#await import('./x.svelte') then { default: X }}<X …/>{/await}`
  (client-only: guard with `browser` from `$app/env` if `ssr: false`).
- Portals: bits-ui `X.Portal`; elsewhere a `{@attach}` that moves the node.

### Server actions (do not rewrite them)
- Import from the generated wrapper with the same names and arguments:
  `import { updateIssue } from '@/lib/actions/tickets'` then
  `await updateIssue(projectId, id, patch)`. Types re-exported from the action
  file are available from the same module.
- The wrapper already does what Next did after an action: awaits
  `refreshAll()` when the action called `revalidatePath`, and follows
  `redirect()` with `goto`. Don't add your own refresh after those.
- Where the React code called `router.refresh()` explicitly, call
  `refreshAll()` from `$app/navigation`.
- Commands can't run during render/SSR: call actions only in event handlers or
  `$effect`. If a React component called an action to **load** data on mount,
  keep doing it in `$effect` (or move it into the page load if that is clearly
  equivalent).
- Never edit `src/app/actions/**`, `src/lib/remote/**`, `src/lib/actions/**`
  (generated). If an action is missing a capability, report it.

### Pages and data loading
- `page.tsx` (async server component) → `+page.server.ts` `load` doing the same
  calls (the shared `getSession()`, `requireProjectMember()` etc. work as-is via
  the shims; `locals.user` is also available) + `+page.svelte` rendering the
  returned data with the same components. `searchParams` → `url.searchParams`,
  `params` → `params`. `redirect('/x')` → `redirect(303, '/x')` from
  `@sveltejs/kit`; `notFound()` → `error(404, 'Not found')`.
- `generateMetadata`/`metadata` → `<svelte:head><title>…</title></svelte:head>`
  with the same titles (root template is `%s · Ticket System`).
- `layout.tsx` → `+layout.server.ts` + `+layout.svelte` (`{@render children()}`).
- Async server components inside `src/components` (project-list, app-shell,
  audit-log-view, sidebar-workspaces, sidebar-favorites): move their data
  fetching into the owning layout/page `load` and pass it as props.
- `loading.tsx` → nothing per page; the dashboard layout shows the navigation
  progress indicator. `error.tsx`/`not-found.tsx` → `+error.svelte` (same UI,
  branch on `page.status`).
- `<Suspense>` with streamed data → return the promise un-awaited from the
  server `load` and render with `{#await}`.

### Navigation and routing helpers
- `<Link href>` → `<a href>`; `prefetch={false}` → `data-sveltekit-preload-data="off"`.
- `useRouter().push(x)` → `goto(x)`; `.replace(x)` → `goto(x, { replace: true })`;
  `.back()` → `history.back()`; `router.refresh()` → `refreshAll()`.
- `usePathname()` → `page.url.pathname`; `useSearchParams()` →
  `page.url.searchParams`; `useParams()` → `page.params` (`import { page } from '$app/state'`).
- `goto()` rejects external URLs: use `window.location.href = url` for them.

### Styling and UI
- **Pixel parity with the React app is required.** Copy Tailwind class
  strings verbatim from the `.tsx`. Use `cn()` from `@/lib/utils` exactly where
  React did.
- Use the ported primitives in `@/lib/components/ui/*` (same names as the React
  ones) — never raw bits-ui in feature code unless the React code used raw
  Radix.
- Icons: `lucide-react` `XIcon` → `@lucide/svelte` (pinned 1.17.0, same paths):
  `import XIcon from '@lucide/svelte/icons/x'` (kebab file name; check the
  package's `dist/icons/` for the exact name). Same `className`/`size`/`strokeWidth` props.
- Toasts: `sonner`'s `toast` → `import { toast } from 'svelte-sonner'` (same API).
- Theme: `next-themes` `useTheme()` → mode-watcher (`mode`, `setMode`,
  `userPrefersMode`) via the wrapper in `src/lib/svelte/theme.svelte.ts`.
- Markdown (`react-markdown` + `remark-gfm`) → `svelte-exmarkdown` with the
  gfm plugin, keeping the same element overrides.
- Drag and drop → `@dnd-kit/svelte` 0.5.3; `move()` comes from
  `dnd-helpers-svelte` (npm alias of `@dnd-kit/helpers@0.5.3`; the Next app
  still uses helpers 0.4).
- Editor → Tiptap 3.31.3 via `svelte-tiptap` 3.0.2 (`createEditor`,
  `EditorContent`, `SvelteNodeViewRenderer`, `NodeViewWrapper`); the shared
  extension list stays in `src/components/editor/extensions.ts` if React-free,
  otherwise port it.

### Rules for parallel lanes
- Only create/edit files you own (your lane's list below). Read anything.
- Never run `npm install`/`npm ci`, never edit `package.json`, `vite.config.ts`,
  `tsconfig*.json`, `src/app.css`, `src/hooks.server.ts` — ask in your report.
- Never run git commands that change state (no add/commit/stash/checkout/reset).
- Check your work with `scripts/kit-check.sh <your paths…>` (it serializes
  svelte-check across lanes and filters to your files). Errors that are only
  "Cannot find module" for a file another lane owns are expected while lanes
  run in parallel — list them, don't stub them.
- Don't start dev servers. Don't touch the database.
- Port **everything** in your files: every prop, branch, keyboard shortcut,
  aria attribute, empty/loading/error state, toast and permission check. If
  something can't be ported 1:1, say exactly what and why.
- Finish with a report: files created, anything not ported, cross-lane
  imports you rely on, deviations from these conventions.

## Waves

**Wave 0 — foundation** (coordinator): config, hooks, shims, generated action
wrappers, styles. Done.

**Wave 1 — primitives and shared state** (3 lanes, must finish before wave 2):
- W1a `ui` primitives part 1: alert-dialog, avatar, button, calendar, card,
  checkbox, collapsible, command, context-menu, dialog, dropdown-menu,
  hover-card, input-group, input, label.
- W1b `ui` primitives part 2: popover, progress, radio-group, scroll-area,
  select, separator, sheet, sonner (Toaster), switch, table, tabs, textarea,
  toggle-group, toggle, tooltip.
- W1c shared client state: `ui-icons/*`, `theme-provider` → `src/lib/svelte/theme.svelte.ts`
  + `ModeWatcher` setup, the React contexts (`project/project-data`,
  `issues/selection`, `issues/display-options`, `issues/issue-filters`,
  `views/view-context`, `navigation/saved-view-context`, `editor/context`),
  the client lib modules (`auth-client`, `undo`, `palette-commands`,
  `hotkeys`, `sync/outbox` store), `src/hooks/use-logout.ts`, and the root
  `src/routes/+layout.svelte` (app.css, ModeWatcher, Toaster, TooltipProvider,
  OfflineBanner/RegisterServiceWorker slots left for L1).

**Wave 2 — feature lanes** (parallel; listed in `docs/migration/LANES.md`).

**Wave 3 — API routes**, then **integration**: full `kit:check`, build, run
against local Postgres with seed data, side-by-side screenshots of every route
against the Next app, fixes. **Reviews**: Codex Sol + Astra (xhigh) and fresh
Claude reviewers per area. **Performance**: JS shipped, TTFB and Lighthouse
on the same pages, Next vs SvelteKit. **Cutover**: delete the Next app, make
`tsconfig.svelte.json` the `tsconfig.json`, move the React-free modules from
`src/components` into `src/lib/components`, Dockerfile/compose/docs/tests.
