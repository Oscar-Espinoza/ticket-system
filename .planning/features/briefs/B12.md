## Build
- **Export**: `GET /api/projects/[id]/export?format=csv|json` (member only) with all non-deleted issues and their properties (key, title, description, state, type, priority, assignee email, creator, labels, estimate, due date, cycle, epic, parent key, created/updated/completed) — proper CSV escaping, `Content-Disposition` filename.
- **CSV import**: upload a CSV (client parses; RFC-4180 incl. quoted newlines), column-mapping step with auto-detection, preview first rows, then import in chunks via a server action using the issue service (`actor { userId }` = importer, admin/member write level): map state by name (fallback default), priority by name, assignee by member email, labels by name (create missing), estimate, due date. **Jira**: same pipeline with a Jira CSV preset (Summary, Description, Status, Priority (Highest/High/Medium/Low/Lowest), Assignee, Labels, Issue key → kept in description footer, Created). **GitHub Issues**: pick a repo (user's token; if absent, explain how to connect in Settings → GitHub), import open (optionally closed) issues (not PRs) with labels (create missing, keep colors), open → default state, closed → first completed; body + link back; cap 500; progress + result summary. Skip duplicates re-imported (by a marker in the description).
- **Insights** `/projects/[id]/insights`: cards + small hand-rolled SVG charts (your own in `components/insights`; accessible, token colours, no chart library): created vs completed per week (12 weeks), open issues by state / priority / assignee / label (bars), cycle time and lead time medians + distribution, throughput per week, filter by date range and label. Compute server-side in `src/lib/insights.ts` with SQL aggregates.
- **PWA**: `manifest.ts` (name, short_name, start_url `/dashboard`, display standalone, theme/background colours from the design tokens, icons — generate simple PNG icons into `public/icons/` from `src/app/icon.svg` if a tool is available, else SVG icons with `purpose: any`), `viewport`/`themeColor` + apple-web-app metadata in the root layout, a registration component (`src/components/pwa/register-sw.tsx`, production only unless `?sw=1`).
- **Offline**: `public/sw.js` — precache the offline page + icons; cache-first for `/_next/static/*`; network-first with cache fallback for navigations (then `/offline`); never cache API routes, server actions (POST) or auth. Offline banner component when `navigator.onLine` is false. Read-only offline; document that queued writes are out of scope.
- **Real-time updates**: `LiveUpdates({ projectId })` polls `GET /api/projects/[id]/changes` every ~5 s while the tab is visible (pause when hidden, immediate check on focus); the endpoint (member only) returns a cheap change token (e.g. max `ticket.updated_at`, max `activity.created_at`, ticket count, for that project); when it changes, `router.refresh()` (debounced, skipped while the user is typing in an input/textarea to avoid clobbering drafts).
- **Presence**: heartbeat `POST /api/projects/[id]/presence { ticketId }` every 15 s (upsert `presence`), `GET` returns members seen in the last 45 s (with the issue they're on); `header-presence.tsx` shows avatars of other people viewing the same issue; `LiveUpdates` may also render a compact avatar stack of people active in the project (fixed, unobtrusive) — your call.
