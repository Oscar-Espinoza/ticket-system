## Structural findings (max 25, most important first)

**A. One issue property, many hand-written renderers/editors (no property registry)**
- [hidden] issues/issue-row.svelte:96-166, views/table-view.svelte:175-285, board/board-card-content.svelte:46-69, issue-detail/issue-detail.svelte:248-332, issues/issue-context-menu.svelte:195-290, issues/slots/bulk-bar.svelte:140-245 — status/priority/assignee/labels/estimate/due/start/cycle/epic each rendered and edited by six separate copies (picker wiring, `canWrite` fork, aria label text, which-chip-for-which-property, muted "—" fallback). Adding a property (or changing a label like "Change status (X)") means editing all six plus display-options.svelte.ts:38 `DisplayProperty`, table `ALL_COLUMNS` (table-view:55) and views/display-menu.svelte:55 `TOGGLEABLE`. Fix idea: one property descriptor table (id, label, read chip, picker, visibility rule) that row/table/card/detail iterate.
- [hidden] issues/issue-context-menu.svelte:125-136 copies issue-pickers/due-date-options.svelte:11-22 `quickOptions` (incl. the "coming Friday" formula); `PRIORITY_MENU` (context-menu:123) copies `MENU_ORDER` (priority-options.svelte:11); viewer-first member sort (context-menu:172-175) copies assignee-options.svelte:26-27; start-date-options.svelte:6-16 is a third near-copy. Fix idea: export the option builders from issue-pickers and let the context menu render them.
- [hidden] issues/issue-row.svelte:79-83 and views/table-view.svelte:130-136 each define `refocusRow` (query by `data-issue-row`, with/without `tr`), board-card/timeline-row/calendar chip have none: pickers return focus differently per view. Fix idea: one `refocusIssue(id)` helper next to ISSUE_ITEM.

**B. The "issue element" DOM contract is string selectors scattered across 8 files**
- [hidden] issues/selection.svelte.ts:29 `ISSUE_ITEM='[data-issue-row], [data-board-card]'` vs issues/issues-view-body.svelte:175 (adds `[data-issue-chip]`), issues/slots/issue-shortcuts.svelte:152,201,208, issues/slots/list-overlay.svelte:16, issues/issue-list.svelte:135,141,168, productivity/issue-actions.ts:~29 `focusedIssueId`, issues/selection.svelte.ts:34 `itemId`. Calendar chips (`data-issue-chip`, views/calendar-draggable-chip.svelte:31) are in some sets and not others, so context menu/selection/shortcuts silently skip them; table `tr` and timeline rows reuse `data-issue-row`, so list-only behaviours (list-overlay Space peek, issue-list `s` hotkey guard) also fire there. Fix idea: one module exporting the attribute names, `ISSUE_ITEM`, `issueIdOf(el)`, `focusedIssueId()`, used everywhere.
- [special:timer] issues/issues-view-body.svelte:173, issues/slots/issue-shortcuts.svelte:157, triage/triage-view.svelte:70, triage/accept-dialog.svelte:41, editor/markdown-editor.svelte:281,320, editor/raw-editor.svelte:128, svelte/focus.ts:11 — rAF/setTimeout(0) used to "wait for the dialog/popover/palette to finish" before focusing. Order is an implicit convention (e.g. issue-shortcuts:157 rAF then `hasOpenLayer()` to guess whether the list opened its own menu: two components racing for the `s` key). Fix idea: a single `focusAfterLayerClose(selector)` and an explicit hotkey claim instead of a rAF race.

**C. Optimistic-update/rollback written per feature instead of one mechanism**
- [hidden] issue-detail/slots/section-relations.svelte:61-90, section-customers.svelte:~70-145 (add/update/remove), header-subscribe.svelte:46-70, section-attachments.svelte, section-similar.svelte, comments/issue-activity.svelte:150-205 — each re-implements: local optimistic copy, `try { result.ok } catch { toast.error('Something went wrong — …') }`, then `resync()` (version++ refetch). Only issues/use-issue-mutations.svelte.ts has outbox/undo/offline; these writes are silently not offline-capable or undoable, and the refetch effect (`let cancelled=false` + `.then`) is repeated in 11 files. Fix idea: a `useRemoteList(fetch, {add,remove})` helper that owns optimistic apply, rollback, toast, refetch.
- [hidden] issues/use-issue-mutations.svelte.ts:360-690 — `update`/`saveCollabDescription` (365-398) are copies differing by one arg; the `label` string `${describePatch(patch)} on ${key}` is built 3x in `update`/`bulkUpdate`; archive/unarchive/remove/restore (445-525) repeat the same run+undo+toast skeleton and `archiveMany`/`removeMany` repeat it again with different strings; the 'Created KEY' path pairs `toast`+`pushUndo` by hand each time. Fix idea: one `commit({op, call, undo, successToast})` and let single = many-of-one.
- [hidden] triage/triage-view.svelte:46-105 keeps its own `handled` set + `running` counter + try/catch (`'Forbidden'` rewritten again) beside a `useIssueMutations` it only uses for `include`; triage state changes bypass the outbox/undo path.
- [special:copied constant] `error === 'Forbidden' ? "You don't have permission…"` is copied 13x: use-issue-mutations.svelte.ts:219, svelte/outbox.svelte.ts:245 (lower-cased variant), issue-detail/slots/{section-attachments:15,section-customers:9,section-relations:8,menu-move:24,menu-extra-items:45,section-similar:99}, comments/issue-activity.svelte:16, cycles/{cycle-form:37,complete-cycle-dialog:46}, triage/triage-view.svelte:90. **D. The views/issues/board folder tangle (value-import cycle)**
- [hidden] issues/ imports views/ chips + view-context + use-sortable-groups (issues/issue-row.svelte:32-37, issues/issue-list.svelte:19, issues/issues-view-body.svelte:12-14) while views/ and board/ import issues/ `display-options`, `selection`, `use-issue-mutations`, `issue-properties`, `group-icon` (views/table-view.svelte:19-43, board/board-card.svelte:14-15, board/board-card-content.svelte:6-9, board/column-header.svelte:5). The registry issues/views.ts statically imports list-view and lazily imports board/table/calendar/timeline, which import back `IssueViewProps` from issues/views. Chips (`cycle-chip`, `epic-chip`, …, `property-chips.ts` barrel) are issue-property display, not "views". Fix idea: move chips/view-context/use-sortable-groups to a neutral `issue-properties/` folder; keep issues/ -> views/ one-way.
- [surplus] views/property-chips.ts barrel is imported by nobody (consumers import each .svelte directly: issue-row:32-36, board-card-content:13-17); issues/issue-properties.ts mixes a re-export barrel with `relativeTime`. Fix idea: delete the barrel; give `relativeTime` a home in lib.

- [special:module-identity] issues/views.ts:44 `loading: 'board'|'rows'|'card'` plus issue-view-host.svelte:50-67 `if (view.lazy?.loading === 'board')`; views/display-menu.svelte:93,108,230 branch on `layout === 'list'|'board'|'timeline'` to decide Display options (grouped, boardColumnsOnly, "Swimlanes"). These belong in lib/.
